## 1. 🔴 B-A1 — `Refresh()` throttle ใช้นาฬิกาที่ตัวเองกำลังตรวจสอบ

```mql5
const long gmt_now = (long)m_src.GmtTime();                       // :166
if(m_last_sample_gmt > 0 && gmt_now > 0 && gmt_now - m_last_sample_gmt < 20)
{
   InvalidateIfBadWindowExpired(gmt_now);
   return false;                                                   // :170
}
```

**นาฬิกาเดินถอยหลัง** (NTP ดึงกลับ · ตั้งเวลาเอง · VM ถูก resume) →
`gmt_now - m_last_sample_gmt` **ติดลบ** → `< 20` เป็นจริง → `Refresh()` **คืน `false` ทันทีทุกครั้ง**

| นาฬิกาถอยหลัง | `Refresh()` ตายไปนาน |
|---------------|---------------------|
| 5 นาที | **5 นาที** |
| 1 ชั่วโมง (DST) | **1 ชั่วโมง** |

### ทำไมข้อนี้ร้ายกว่าที่ดู

`FarmExecutor.mq5:92` เรียก `Refresh()` ทุก 1 วินาที และ **การคืน `true` คือทางเดียว**
ที่ `BROKER_TIME_OFFSET_CHANGED` จะถูก log และส่งออก

→ ช่วงที่ตาบอด **ไม่มีใครรู้ว่า offset เปลี่ยน** · ไม่มี log ไม่มี ERROR
· เส้นแบ่งวัน R6 ขยับทั้งระบบเงียบๆ — **ซึ่งคือสิ่งที่ B15 ถูกเขียนขึ้นมาเพื่อป้องกันโดยตรง**

> **และช่วงที่นาฬิกากระโดดคือช่วง DST พอดี** — คือเหตุการณ์เดียวที่โมดูลนี้มีไว้จับ
> โมดูลจึงตาบอดตรงเวลาที่มันควรตื่นที่สุด

### แก้

```mql5
// ใช้แหล่งเวลาที่เดินหน้าอย่างเดียว ไม่ใช่นาฬิกาผนัง
uint now_tick = GetTickCount();
if(m_last_sample_tick != 0 && (int)(now_tick - m_last_sample_tick) < 20000)
   return false;
```

**cast เป็น signed ก่อนเทียบเสมอ** — สำนวนเดียวกับ **S1(d)** และ **S5** ใน `Wire.mqh`
· `GetTickCount()` wrap ทุก ~49.7 วัน แต่ผลต่างแบบ unsigned ยังถูกต้องข้าม wrap (ดู §5)

## 2. 🔴 B-A2 — หน้าต่าง 90 วินาทีก็วัดด้วยนาฬิกาผนังเดียวกัน

```mql5
if(gmt_now - m_bad_sample_started_gmt > 90)      // :97
{
   m_valid = false;
   m_candidate_count = 0;
}
```

หน้าต่างนี้วัด **ผลต่างของค่านาฬิกา ไม่ใช่ระยะเวลาที่ผ่านไปจริง**

| นาฬิกา | ผล |
|--------|-----|
| กระโดดไปข้างหน้า ระหว่างหน้าต่างเปิดอยู่ | หน้าต่าง**สั้นลง** → invalid เร็วกว่าที่ควร |
| เดินถอยหลัง | ผลต่างติดลบ → **ไม่มีวัน `> 90`** → ค้างในสถานะ `valid` ทั้งที่ sample เสียตลอด |

**เคสที่สองคือ fail-open** — โมดูลที่ออกแบบมาให้ *fail-closed* (ไม่แน่ใจ → invalid → SafeMode)
กลับ**คงสถานะ valid ไว้แล้วให้ค่า offset เก่าต่อไปเรื่อยๆ** ซึ่งอันตรายกว่าการ invalid ผิด

**แก้:** จับเวลาหน้าต่างด้วย tick เดียวกับ B-A1 · ตัวแปรเป็น `uint` + เทียบแบบ signed

> **ทั้ง B-A1 และ B-A2 คือบั๊กตัวเดียวกันที่โผล่สองที่** — เก็บ "เวลาที่เกิดเหตุ" เป็นค่านาฬิกาผนัง
> แล้วเอามาลบกันภายหลัง · [SPEC-063 §4.7](../specs/SPEC-063-broker-time.md) เขียนกฎนี้ไว้เองว่า
> *"อย่าเดาจากค่าที่เก็บไว้ ให้ดูจากของจริง"* — ตรงนี้ยังทำตรงข้ามอยู่

## 3. 🟠 B-A3 · B-A4 — สองข้อที่เกี่ยวกับการ re-init

### B-A3 `Init()` นับเวลาด้วยการบวก ไม่ได้วัด

```mql5
while(elapsed_ms < 3000) { ... m_src.SleepMs(200); elapsed_ms += 200; }   // :144-155
```

`Sleep(200)` ไม่รับประกันว่าคืนใน 200 ms · **ตอน terminal เพิ่งบูตคือช่วงที่มันยืดที่สุด**
→ งบ "3 วินาที" จริงอาจเป็น 10 วินาที · EA ค้างใน `OnInit` นานกว่าที่ออกแบบ

**ไม่ร้ายแรง** (แค่พยายามนานกว่าที่คิด ไม่ใช่สั้นกว่า) แต่ควรวัดจาก `GetTickCount()` จริง

### B-A4 `Init()` เรียก `Reset()` → ประวัติ offset หายทั้งหมด

`Reset()` ล้าง `m_last_change_utc` · `m_previous_offset_sec` · `m_detected_at_utc`

**เรารู้แล้วว่า EA ถูก `OnInit` ซ้ำเองตอน terminal บูต** ([chaos รอบ 3](SPEC-016-chaos-03.md))
→ ถ้า DST เปลี่ยนคร่อมการ re-init นั้น **จะไม่มีใครรู้เลย** เพราะ:

- `Init()` → `AcceptOffset(detected, **true**)` → `initial=true` → **คืน `false` เสมอ**
- `FarmExecutor:92` รายงานเฉพาะตอน `Refresh()` คืน `true`

**แก้:** เก็บ offset ล่าสุดข้ามการ re-init (global/static หรือไฟล์) แล้วเทียบตอน `Init`
· ถ้าต่างจากเดิม → log `BROKER_TIME_OFFSET_CHANGED` พร้อม flag ว่ามาจากการ re-init

## 5. 🟢 ตรวจแล้ว **ไม่พัง** — ห้ามไปแก้

| ข้อกังวลที่ฟังดูสมเหตุผล | ความจริงหลังไล่เลข |
|---------------------------|---------------------|
| `RoundToNearest` สาขาค่าลบเขียนแยก น่าจะไม่สมมาตร | **ถูกต้อง** — `-3601` → `-3600` · `-450` → `-900` แล้วโดน guard `>120` ตัดทิ้ง เหมือนฝั่งบวกเป๊ะ |
| `AcceptOffset` เงื่อนไข `!initial && !was_valid && detected != old` ซับซ้อนน่าจะมีรู | **ถูกต้อง** — ที่ call site เดียวที่ `initial=false` (`Refresh():185`) ถูกป้องด้วย `if(!m_valid)` อยู่แล้ว → `!was_valid` จริงเสมอ → เทียบเท่า `detected != old` ตรงตาม **B15** |
| `:207` `m_last_change_utc = BrokerToUtc(m_last_server)` ใช้ offset ผิดตัว | **ถูกต้อง** — `m_offset_sec` ถูกอัปเดตที่ `:206` ก่อนแล้ว และ `m_last_server` ถูกอ่าน**ภายใต้ระบอบใหม่** จึงต้องแปลงด้วย offset ใหม่ |
| `datetime` unsigned จะ underflow อีก (B16b) | **ปิดแล้วจริง** — ไม่เหลือการลบ `datetime` ตรงๆ · `m_bad_sample_started_gmt` · `m_last_sample_gmt` เป็น `long` ทั้งคู่ ✅ |
| ขอบเขต `-43200 / +50400` | **ถูก** — −12h ถึง +14h ครอบ timezone จริงทั้งโลก |

**เขียนไว้เพราะ 5 ข้อนี้ดูน่าสงสัยพอที่จะทำให้มีคน "แก้ไว้ก่อน"** แล้วเพิ่มความซับซ้อนโดยไม่ได้อะไร
