## 3. S1 — ข้อมูลชุดใหม่ที่สะอาดกว่าเดิม

```
heartbeats = 1532 ใน 3598.0 วินาที
mean_gap   = 2.350s          (สัญญา 2.000s)
median     = 2.015s
max        = 3.016s
histogram  = {2: 995, 3: 536}        ← มีแค่จำนวนเต็มสองค่า เหมือนเดิม
```

| | รอบ 1 | รอบ 2 |
|---|-------|-------|
| ตัวอย่าง | 653 | **1531** |
| mean_gap | 2.436s | **2.350s** |
| สัดส่วนที่ตกเป็น 3 วินาที | 42% | **35%** |

**ค่าไม่คงที่ระหว่างรอบ (42% → 35%) — ซึ่งเป็นหลักฐานเพิ่มว่า [การวินิจฉัยใน rev.7 ถูก](SPEC-001-timing-audit.md)**
ถ้าเป็นการปัดเศษล้วนๆ สัดส่วนควรคงที่ · การที่มันขยับตามรอบแปลว่าขึ้นกับ
**ความหน่วงของคอลแบ็กในรอบนั้น** ซึ่งคือสิ่งที่ฐานรีเซ็ตที่ `Wire.mqh:612` สะสมเข้าไป

### เกณฑ์ `1700` ควรเป็นเท่าไร (S3)

```
int(SOAK_SECONDS / HEARTBEAT_SEC * 0.95) = int(3600 / 2 * 0.95) = 1710
```

`1700` ที่ใช้อยู่**ต่ำกว่าเกณฑ์ที่อนุมานจากสัญญา 10 ตัว** — ไม่กระทบผลรอบนี้ (1532 ตกทั้งสองเกณฑ์)
แต่ต้องแก้ตาม S3 เพื่อให้ขยับตามถ้าใครเปลี่ยน `InpHeartbeatSec`

**หลังแก้ S1 ต้องได้ ~1799** (3598/2) · ถ้าได้ต่ำกว่า **1710** = ยังไม่หาย
