**วันที่:** 2026-08-01 · **โดย:** Claude · **สถานะ:** ⚠️ **แก้คำที่ผมเขียนผิดเองใน work-order**

ทำก่อน Codex ส่งงาน เพื่อให้ตอน review รอบ S2 ผมมี**คำตอบของตัวเอง**เทียบ
ไม่ใช่อ่านรายงานแล้วพยักหน้า · ครอบคลุม **ทุกจุด** ที่แตะนาฬิกาใน `mt5-ea/`

## 0. 🔴 ข้อแรกสำคัญที่สุด — **`/1000` ไม่ใช่ต้นเหตุของ S1**

work-order ข้อ S1 ของผมเขียนว่าต้นเหตุคือ *"การปัดเศษวินาที"* และสั่ง S2 ให้ไล่หา
*"อคติ −0 ถึง −999 ms"* ทุกจุดที่เรียก `ElapsedSec()`

**ผมพิสูจน์แล้วว่าข้อความนั้นผิด** — ตรวจด้วยคณิตศาสตร์ตรงๆ:

```
ElapsedSec(x) = floor(e / 1000)          e = มิลลิวินาทีที่ผ่านไปจริง
floor(e/1000) >= K   ⟺   e >= K*1000     ← ตรงเป๊ะ ไม่เร็วไม่ช้า
```

→ **ทุกจุดที่เทียบด้วย `>=` หรือ `<` ยิงที่เวลาถูกต้องพอดี ไม่มีอคติแม้แต่มิลลิวินาทีเดียว**
`ElapsedSec()` ไม่ได้ทำให้ heartbeat เพี้ยน · ถ้าไล่ตาม S2 ฉบับเดิมจะไล่ไม่เจออะไรเลย
แล้วสรุปผิดว่า "จุดอื่นไม่เป็นไร"

### ต้นเหตุจริงของ S1 = **ฐานเวลาถูกรีเซ็ต + timer granularity 1 วินาที**

```mql5
EventSetTimer(1);                      // FarmExecutor.mq5:80  ← poll ได้แค่ทุก 1 วินาที
...
m_last_heartbeat_tick = NowTick();     // Wire.mqh:612         ← ฐานเลื่อนตามเวลาส่งจริง
```

| tick | e ตั้งแต่ฐาน | `e >= 2000`? | ผล |
|------|--------------|--------------|-----|
| +1000 | 1000 | ไม่ | — |
| +2000 | **1999** ← ฐานขยับมา 1 ms | **ไม่** | พลาด |
| +3000 | 2999 | ใช่ | **gap = 3 วินาที** |

ความหน่วงในคอลแบ็กถูกบวกเข้าฐานใหม่ทุกรอบ → ฐานเลื่อนออกจากเส้น tick เรื่อยๆ
→ ~42% ของรอบพลาด tick ที่ 2 → **histogram มีแค่ `{2.0, 3.0}` พอดีตามที่วัดได้**

> ### ⛔ ผลต่อ Codex — ข้อนี้ทำให้แผน A2 เปลี่ยน
>
> **ถ้าทำแค่ S1(a)** (เปลี่ยนไปเทียบเป็นมิลลิวินาที) **แล้วยังคง `= NowTick()` ไว้ — บั๊กจะยังอยู่ครบ**
> เพราะปัญหาไม่เคยอยู่ที่หน่วยที่ใช้เทียบ
>
> **S1(b) `next_due += interval` คือข้อที่แก้ปัญหา** — และมันแก้ได้จริงเพราะ `next_due`
> เลื่อนทีละ 2000 พอดี จึงอยู่บนเส้น tick ตลอด ไม่มีวันหลุด
> · **S1(a) ยังต้องทำ** แต่เป็นของที่ทำให้ (b) เขียนได้ ไม่ใช่ตัวแก้

## 2. 🟢 สิ่งที่ผมตรวจแล้วว่า **ไม่พัง** — ห้ามใครไป "แก้"

| ข้อกังวลที่ฟังดูสมเหตุผล | ความจริง |
|---------------------------|----------|
| *"`NowTick() - since_tick` เป็น unsigned จะ underflow ตอน wrap"* | **ไม่พัง** — เลขคณิต modulo ให้ผลต่างที่ถูกต้องเสมอถ้า elapsed < 49.7 วัน · **การลบปลอดภัย อันตรายอยู่ที่การเปรียบเทียบ (§4)** |
| *"`(int)` cast จะติดลบเหมือน B16b"* | **ไม่พัง** — `/1000` เกิด**ก่อน** cast → ค่าสูงสุด `2³²/1000 ≈ 4,294,967` ห่างจากขอบ int32 อยู่ 500 เท่า |
| *"`m_last_heartbeat_tick = 0` ตอนสร้าง → ElapsedSec(0) = uptime"* | **ไม่พัง** — ได้ค่าบวกมหาศาล → `>= 2` เป็นจริง → ส่ง heartbeat ทันที ซึ่งคือพฤติกรรมที่ต้องการ |
| *"`SecondsSinceLastInbound()` = uptime ถ้ายังไม่เคยรับอะไร"* | **ไม่พัง** — ผู้เรียกที่ `FarmExecutor.mq5:109` มี `IsAuthenticated()` คุมอยู่ ซึ่งแปลว่ารับ HELLO_ACK มาแล้ว → `m_last_inbound_tick` ถูกตั้งแล้วเสมอ |

**เขียนไว้เพราะ 4 ข้อนี้ฟังดูน่ากลัวพอที่จะทำให้มีคน "แก้ให้ปลอดภัยไว้ก่อน"**
แล้วเพิ่มความซับซ้อนโดยไม่ได้อะไร · ทุกข้อผมไล่เลขแล้ว

## 3. 🔴 finding ใหม่ **S4** — brain timeout ยิงช้าไป 1 วินาทีเต็ม

```mql5
// FarmExecutor.mq5:14   input int InpBrainTimeoutSec = 10;
// FarmExecutor.mq5:109
if(g_wire.IsAuthenticated() && g_wire.SecondsSinceLastInbound() > InpBrainTimeoutSec)
```

`SecondsSinceLastInbound()` คืน `floor(e/1000)` · ผู้เรียกใช้ **`>`** ไม่ใช่ `>=`

```
floor(e/1000) > 10   ⟺   e >= 11,000 ms
```

**ตั้งไว้ 10 วินาที แต่ยิงจริงที่ 11.000 วินาที** — ไม่ใช่ jitter แต่เป็น **+1 วินาทีเต็มเสมอ**

| | |
|---|---|
| ผลวันนี้ | แค่ `Warn` ช้าไป 1 วินาที — ยังไม่เจ็บ |
| **ผลเมื่อ [SPEC-023](../specs/SPEC-023-safemode.md) ขึ้น** | **R16 brain timeout → SafeMode** · เกณฑ์ที่ Phase 1 exit บังคับคือ *"kill brain → SafeMode ≤ 10s"* — **โค้ดนี้ทำได้ 11s ตกเกณฑ์ทันที** |

### ต้องแก้ — เลือกทางใดทางหนึ่ง **แล้วเขียนเหตุผล**

| ทาง | ทำ | ข้อดี |
|-----|-----|-------|
| **A (แนะนำ)** | เพิ่ม `MsSinceLastInbound()` คืน `uint` แล้วให้ `:109` เทียบ `>= InpBrainTimeoutSec * 1000` | ตรงเป๊ะ · เข้ากับ S1(a) ที่กำลังทำอยู่แล้ว |
| B | เปลี่ยน `>` เป็น `>=` ที่ `:109` | 1 อักขระ แต่ยังหยาบระดับวินาที |

**ห้ามปล่อยไว้** — ค่านี้จะกลายเป็นเกณฑ์ที่ Phase 1 exit วัด และมันจะตกด้วยเหตุผลที่ไม่มีใครเดาถูก

## 4. 🟠 finding ใหม่ **S5** — เทียบ unsigned ดิบที่ `:786` (ที่ S1(d) ห้ามไว้เอง)

```mql5
m_next_connect_tick = NowTick() + (uint)wait_ms;   // :254
...
if(m_state == WIRE_DISCONNECTED && NowTick() < m_next_connect_tick)   // :786  ← ห้ามตามข้อ S1(d)
   return;
```

S1(d) เขียนไว้ว่า *"ห้าม `NowTick() >= m_next_heartbeat_tick` ตรงๆ"* — **จุดนี้ทำสิ่งนั้นอยู่แล้ววันนี้**

### ผมไล่ทั้งสองเคสของการ wrap แล้ว — **ไม่ใช่การค้างถาวร**

| เคส | เกิดอะไร |
|-----|---------|
| `NowTick() + wait` **ไม่ล้น** | `NowTick()` เดินถึงค่านั้นก่อน wrap เสมอ → **ทำงานถูกต้อง** |
| `NowTick() + wait` **ล้น** → ค่าน้อย | `now`(มหาศาล) `< next`(น้อย) เป็นเท็จ → **reconnect ยิงทันที เร็วกว่ากำหนดสูงสุด 30 วินาที** |

**ความเสียหายจริง: backoff ถูกข้าม 1 ครั้ง ทุก ~49.7 วันของ uptime** — ไม่ร้ายแรง
แต่ **ต้องแก้ในรอบ A2 เพราะ Codex เปิดไฟล์นี้อยู่แล้ว** และเพราะปล่อยไว้ = โค้ดขัดคำสั่งของตัวเอง

**แก้:** `if((int)(NowTick() - m_next_connect_tick) < 0) return;` — ผลต่าง unsigned แล้ว cast signed
ทนต่อ wrap ทุกกรณี · เป็นสำนวนเดียวกับที่ S1(d) ต้องการ

> ★ **สังเกตว่า S5 คือหลักฐานว่า §0 ถูก** — อันตรายของ unsigned อยู่ที่**การเปรียบเทียบ** (`:786`)
> ไม่ใช่**การลบ** (`:128`) · work-order ฉบับเดิมชี้ผิดจุดทั้งคู่

## 5. 🟡 บันทึกไว้ ไม่ต้องแก้ตอนนี้ — jitter ใช้ `GetTickCount()` เป็นตัวสุ่ม

`:207` `(int)(GetTickCount() % (uint)(jitter * 2 + 1)) - jitter`

`GetTickCount()` เดินเป็นเส้นตรง ไม่ใช่ค่าสุ่ม → ถ้า reconnect เกิดเป็นจังหวะสม่ำเสมอ
jitter ที่ได้จะ**สหสัมพันธ์กับจังหวะนั้น** แทนที่จะกระจาย

**ยังไม่กระทบอะไรวันนี้** (EA ตัวเดียว) · แต่เมื่อถึง Phase 6 ที่มี 5+ terminal
jitter มีไว้เพื่อ**กัน thundering herd** — ถ้ามันไม่สุ่มจริง มันก็ไม่ได้กัน
→ **ยกไปเป็นหนี้ที่ต้องปิดก่อน Phase 6** ไม่ใช่ตอนนี้
