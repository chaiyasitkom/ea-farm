## 2. ต้นเหตุ — `Wire.mqh:126-129` + `:612`

```mql5
int ElapsedSec(const uint since_tick) const
{
   return (int)((NowTick() - since_tick) / 1000);   // ← integer division ตัดเศษทิ้ง
}
```

```mql5
if(SendRawLine(msg))
{

   m_last_heartbeat_tick = NowTick();              // ← จุดอ้างอิงรีเซ็ตเป็น "เวลาที่ส่งสำเร็จ"

```

**ลำดับที่ผลิต 3 วินาที:**

| tick | elapsed จริง | `ElapsedSec()` | ผล |
|------|---------------|----------------|-----|
| ส่ง heartbeat | — | — | ประทับ `m_last_heartbeat_tick` **หลังทำงานในคอลแบ็กไปแล้วบางส่วน** |
| `OnTimer` +1 | ~1000 ms | 1 | ยังไม่ถึงกำหนด ✓ ถูกต้อง |
| `OnTimer` +2 | **~1998 ms** | **1** | ← **ขาด 2 มิลลิวินาที → ข้าม** |
| `OnTimer` +3 | ~2998 ms | 2 | ส่ง → **กลายเป็น 3 วินาที** |

**สองอย่างประกอบกันถึงจะพัง:**

| # | | |
|---|---|---|
| ก | `/1000` ตัดเศษ | 1999 ms ถูกมองเป็น 1 วินาที |
| ข | จุดอ้างอิงเลื่อนตามเวลาส่งจริง | ความหน่วงในคอลแบ็กถูกบวกเข้าไปใหม่**ทุกรอบ** ไม่มีการชดเชย |

ข้อ ข คือตัวที่ทำให้มันไม่หายเอง — ถ้าจุดอ้างอิงเป็นตารางตายตัว ความหน่วงจะถูกกลืนในรอบถัดไป
· อัตราส่วนที่วัดได้ **104:86** = ประมาณ 45% ของรอบตกใต้เส้น ซึ่งสอดคล้องกับ jitter ของ `OnTimer(1)` บวกงานใน `Pump()`

> 📌 `ElapsedSec()` ถูกใช้ที่อื่นด้วย — **ต้องไล่ทุกจุดที่เรียก ไม่ใช่แก้เฉพาะ heartbeat**
> ทุกที่ที่เทียบ "ครบ N วินาทีหรือยัง" ด้วยฟังก์ชันนี้มีอคติต่ำกว่าความจริงได้ถึง 1 วินาที

## 4. สิ่งที่ต้องทำ

### S1 🔴 heartbeat ต้องเดินบนตารางตายตัว · เทียบเป็นมิลลิวินาที

**ห้ามแก้ด้วยการผ่อนเกณฑ์ test** — เกณฑ์ 1700 ถูกต้องแล้ว ดู §4.2

| # | ต้อง | ห้าม |
|---|------|------|
| a | เทียบด้วย **มิลลิวินาที** ไม่ผ่าน `ElapsedSec()` ที่ `/1000` | ห้ามใช้ `>= InpHeartbeatSec` กับค่าที่ตัดเศษแล้ว |
| b | จุดอ้างอิงเลื่อนแบบ **`next_due += interval`** ไม่ใช่ `= NowTick()` | ห้ามรีเซ็ตเป็นเวลาส่งจริง |
| c | ถ้าตกหลังหลายรอบ (เครื่องหยุด/หน่วงยาว) ให้ **ตามให้ทันโดยไม่ยิงรัว** — ดันฐานไปที่รอบถัดไปที่ยังไม่เลยกำหนด | ห้ามส่งชดเชยย้อนหลังทีเดียวหลายอัน |

snippet เชิงหลักการ (ไม่ใช่โค้ดสำเร็จ — Codex เป็นคนเขียนจริง):

```mql5
// เดิม: จุดอ้างอิงรีเซ็ตเป็นเวลาส่ง -> ความหน่วงสะสมทุกรอบ
// m_last_heartbeat_tick = NowTick();

// ใหม่: ตารางตายตัว เทียบ ms ตรงๆ
const uint interval_ms = (uint)m_heartbeat_sec * 1000;
if(m_next_heartbeat_tick == 0)
   m_next_heartbeat_tick = NowTick() + interval_ms;
else if((int)(NowTick() - m_next_heartbeat_tick) >= 0)   // cast เป็น signed กัน wrap
{
   SendHeartbeat();
   m_next_heartbeat_tick += interval_ms;                 // ← เลื่อนบนตาราง ไม่ใช่ = NowTick()
   // ตามให้ทันถ้าตกหลังหลายรอบ โดยไม่ยิงรัว
   if((int)(NowTick() - m_next_heartbeat_tick) >= 0)
      m_next_heartbeat_tick = NowTick() + interval_ms;
}
```

⚠️ `GetTickCount()` เป็น `uint` **wrap ทุก ~49.7 วัน** → การเทียบต้อง cast เป็น signed เสมอ
ห้ามเขียน `NowTick() >= m_next_heartbeat_tick` ตรงๆ · เป็นบั๊กประเภทเดียวกับ **B16b** ใน [SPEC-063](../specs/SPEC-063-broker-time.md)
ที่ `datetime` เป็น unsigned แล้ว underflow — **โปรเจกต์นี้เจอกับดัก unsigned เป็นครั้งที่สองแล้ว**

### S2 🟠 ไล่ทุกจุดที่เรียก `ElapsedSec()`

ฟังก์ชันนี้มีอคติ **−0 ถึง −999 ms เสมอ** · ทุกที่ที่ใช้ตัดสิน "ครบเวลาหรือยัง" ต้องทบทวน
· รายงานในหน้า handoff ว่าแต่ละจุดยอมรับได้หรือต้องแก้ **พร้อมเหตุผลรายจุด** ห้ามเหมารวมว่า "จุดอื่นไม่เป็นไร"

### S3 🟠 เกณฑ์ 1700 ต้องมีที่มา ไม่ใช่เลขลอย

`self.assertGreaterEqual(len(heartbeats), 1700)` — เลขนี้ถูกต้องโดยบังเอิญ แต่ไม่มีใครอ่านออกว่ามาจากไหน

```python
# ต้องอนุมานจากสัญญา ไม่ใช่ฝังเลข
EXPECTED = int(SOAK_SECONDS / HEARTBEAT_SEC * 0.95)   # 3600/2 * 0.95 = 1710
```

**ประโยชน์จริง:** ถ้าใครเปลี่ยน `InpHeartbeatSec` เป็น 5 เกณฑ์จะขยับตาม แทนที่จะตกโดยไม่มีใครรู้ว่าทำไม

**ไม่ว่าจะรัน fast gate อีกกี่ครั้งก็ไม่มีทางเจอ** เพราะโครงสร้างของมันไม่ได้วัดสิ่งนี้

>
> รูปแบบร่วม: **"มีเครื่องมืออยู่" ถูกนับเป็น "ถูกตรวจแล้ว"** ทั้งที่มันไม่เคยทำงาน

**ข้อบังคับที่จะเพิ่มเข้า [SPEC-009](../specs/SPEC-009-ci.md) และ [SPEC-065](../specs/SPEC-065-mql5-test-harness.md):**

**วันที่รันล่าสุดของ slow gate** — ถ้าเก่ากว่า N วัน ให้ถือว่า phase exit ยังไม่ผ่าน

| เกณฑ์ 3.5s เท่ากับ max_gap ที่ยอมรับได้ **เป๊ะ** | ไม่เหลือที่ให้ความหน่วงของการสังเกตเลย · ค่าที่ตก **3.547** เกินมา **47 มิลลิวินาที** |
| ข้อความตอนตกไม่บอกว่าใครผิด | อ่านแล้วนึกว่า EA พัง ทั้งที่ EA ปกติ |

**ต้องแยกสองอย่างนี้ออกจากกัน:**

| วัดอะไร | จากไหน | เกณฑ์ |
|---------|--------|-------|
| **EA ยังมีชีวิต** | ไทม์ไลน์ `pump` ใน diag file | ห้ามมีช่องว่าง > 3s |
| **heartbeat ถึง server** | event log ของ server | max_gap ≤ 3.5s **คิดหลังรอบจบ ไม่ใช่ในลูป** |

watchdog ในลูปยังต้องมี (C12 — ห้ามรอครบชั่วโมงแล้วค่อยรู้) แต่ต้องตั้งที่ **~10s**
และเมื่อยิงต้อง**พิมพ์ไทม์ไลน์ทั้งสองฝั่ง**เพื่อให้อ่านออกทันทีว่าฝั่งไหนหยุด

### 7.4 🟠 N3 — diag stream ไม่มีเหตุการณ์ "ส่ง heartbeat"

diag มี `pump` · `inbound` · `state` แต่**ไม่มี `heartbeat_sent`**

→ จึงตอบไม่ได้ว่าช่อง 10.8 วินาทีเกิดจาก **EA ไม่ได้ส่ง** หรือ **server ไม่ได้รับ/ไม่ได้บันทึก**
· ข้อมูลที่มีชี้ว่า EA ปกติ (§7.2) แต่ **นั่นเป็นการอนุมาน ไม่ใช่การวัดตรง**

**เพิ่มบรรทัดเดียวปิดช่องนี้ได้ถาวร** — บทเรียนเดียวกับรอบ W1 ที่จบเพราะ `FileFlush()` diag
*ไม่ใช่เพราะเดาถูก* · [chaos รอบ 3](SPEC-016-chaos-03.md) เขียนไว้แล้วว่า **"เดาผิด 2 ครั้ง → ลงทุนกับการมองเห็น"**
