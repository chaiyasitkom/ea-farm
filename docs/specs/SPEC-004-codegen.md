### 3.2 ฝั่ง Python — pydantic v2

1 class ต่อ 1 payload + `FarmEnvelope` + enum classes

```python
class HelloPayload(BaseModel):
    model_config = ConfigDict(extra="ignore")   # ★ ห้ามเป็น "forbid"
    token: str
    ea_version: str
    ...
```

| schema | Python |
|--------|--------|
| `"const": 1` | `Literal[1]` |
| `"const": true` | `Literal[True]` |
| `enum` | `class XxxEnum(str, Enum)` |
| `"type": ["number","null"]` | `Optional[float]` — **ไม่มี default ถ้าอยู่ใน `required`** |
| field ที่ไม่อยู่ใน `required` | `Optional[X] = None` |
| `ts_utc` | **`str`** ไม่ใช่ `datetime` — ดู §4.3 |
| `ulid` / `symbol` / `session_id` | `str` + `Field(pattern=...)` |
| `volume_map` / `count_map` | `Dict[str, float]` / `Dict[str, int]` |
| nested object | nested `BaseModel` |
| array of object | `List[NestedModel]` |

`ConfigDict(extra="ignore")` **บังคับทุก class** — ถ้าเป็น `forbid` การเพิ่ม optional field
จะกลายเป็น breaking change ซึ่งขัด [§7](../02-contracts.md) ทั้งหมด

> ใช้ `datamodel-code-generator` หรือเขียนเองก็ได้ — **spec นี้กำหนดผลลัพธ์ ไม่ได้กำหนดเครื่องมือ**
> ถ้าใช้ lib ต้อง pin เวอร์ชันเป๊ะและ output ต้อง deterministic (§4.1)

### 3.3 ฝั่ง MQL5 — struct + serializer + parser

```mql5
// ---- enum: prefix FARM_ กันชนกับ constant ของ MQL5 ----
enum ENUM_FARM_MSG_TYPE { FARM_MSG_HELLO, FARM_MSG_HELLO_ACK, ... , FARM_MSG_UNKNOWN };
enum ENUM_FARM_SIDE     { FARM_SIDE_BUY, FARM_SIDE_SELL };
// ...ทุก enum ใน schema

// ---- แปลง enum ↔ string (ต้องมีทั้งสองทาง ทุก enum) ----
string             FarmSideToString(const ENUM_FARM_SIDE v);
ENUM_FARM_SIDE     FarmSideFromString(const string s, bool &ok);

// ---- envelope: parse 2 จังหวะ ----
struct FarmEnvelope
{
   int                 v;
   ENUM_FARM_MSG_TYPE  type;
   string              type_raw;      // เก็บ string ดิบไว้ด้วย เผื่อ type ไม่รู้จัก
   string              msg_id;
   string              session_id;
   string              ts_server;
   string              ts_sent;
   string              payload_json;  // ★ ยังไม่ parse — ให้ parser ตาม type ทำต่อ
};
bool FarmParseEnvelope(const string line, FarmEnvelope &out);
bool FarmSerializeEnvelope(const FarmEnvelope &src, string &out_line);

// ---- payload: 1 struct + 2 ฟังก์ชัน ต่อ 1 type ----
struct FarmHelloPayload { ... };
bool FarmSerializeHello(const FarmHelloPayload &src, string &out_json);
bool FarmParseHello(const string json, FarmHelloPayload &out);

// ---- error ----
string FarmLastParseError();      // ว่าง = ไม่มี error · ต้องบอก field ที่พัง
```

**ทำไม envelope parse 2 จังหวะ:** `type` ที่ไม่รู้จักต้องข้ามได้โดยไม่ปิด connection
([§7](../02-contracts.md) forward compat) ถ้า parse ทั้งก้อนทีเดียวจะ fail ทั้ง message

#### การ map ชนิดข้อมูลลง MQL5

| schema | MQL5 | หมายเหตุ |
|--------|------|----------|
| `integer` | `long` | **ห้ามใช้ `int`** — `ticket` เกิน 2³¹ ได้ |
| `number` | `double` | |
| `string` | `string` | |
| `boolean` | `bool` | |
| `"type": ["number","null"]` | `double x;` **+ `bool x_is_null;`** | ดู §4.4 |
| `"type": ["string","null"]` | `string x;` + `bool x_is_null;` | |
| `enum` | `ENUM_FARM_*` | + `string x_raw` ถ้าเป็น enum ที่ยอมรับค่าใหม่ได้ |
| nested object | nested `struct` | |
| array of object | `Nested arr[];` (dynamic) | `ArrayResize` |
| `volume_map` | `string k[]; double v[];` | **สอง array ขนานกัน** MQL5 ไม่มี map |
| `count_map` | `string k[]; long v[];` | |
| field ที่ไม่อยู่ใน `required` | + `bool x_present;` | แยกจาก `x_is_null` — ดู §4.4 |

### 3.5 ★ `JsonCore.mqh` — tokenizer จริง (ตัวยากที่สุด)

**`Json.mqh` ที่มีอยู่ใช้ไม่ได้กับ ticket นี้** — `FarmJsonGetString()` ทำงานด้วย
`StringFind` หา `"key"` แล้วอ่านค่าถัดไป ซึ่งพังทันทีเมื่อ:

- มี key ชื่อเดียวกันใน nested object (`symbol` อยู่ทั้งใน payload และใน `positions[]`)
- ค่าเป็น string ที่**มีชื่อ key อื่นอยู่ข้างใน** เช่น `"comment": "sl:1.0800"`
- ต้องอ่าน array ของ object (`STATE.positions[]`)

ต้องเขียน **recursive-descent parser** จริง:

```mql5
enum ENUM_FARM_JSON_TYPE { FARM_JSON_NULL, FARM_JSON_BOOL, FARM_JSON_NUMBER,
                           FARM_JSON_STRING, FARM_JSON_ARRAY, FARM_JSON_OBJECT };

class CFarmJsonValue
{
public:
   ENUM_FARM_JSON_TYPE Type() const;
   bool     IsNull() const;
   // object
   bool     Has(const string key) const;
   CFarmJsonValue *Get(const string key);        // NULL ถ้าไม่มี
   // array
   int      Size() const;
   CFarmJsonValue *At(const int i);              // NULL ถ้าเกิน
   // scalar
   bool     AsBool(bool &ok) const;
   double   AsDouble(bool &ok) const;
   long     AsLong(bool &ok) const;
   string   AsString(bool &ok) const;
   // object key list (สำหรับ volume_map)
   int      KeyCount() const;
   string   KeyAt(const int i) const;
};

class CFarmJsonDoc
{
public:
   bool             Parse(const string json);    // false + LastError() ถ้าพัง
   CFarmJsonValue  *Root();
   string           LastError() const;           // ต้องบอกตำแหน่ง/บริบท
   void             Free();                      // ★ ต้องคืนหน่วยความจำครบ
};
```

**ข้อบังคับ:**
- จำกัดความลึก **≤ 32 ชั้น** เกินแล้ว `Parse` คืน false (กัน stack overflow จาก input ที่ตั้งใจร้าย)
- ต้อง `Free()` ครบ — EA รัน 24/7 memory leak สะสมจะทำให้ terminal ตาย
  (acceptance §6 มีข้อวัด leak)
- unescape ครบ: `\" \\ \/ \b \f \n \r \t \uXXXX`

## 4. Behaviour

### 4.1 ★ Determinism — `codegen` สองครั้งต้องได้ไฟล์ byte-identical

`codegen-check` ใช้ `git diff --exit-code` → output ที่ไม่ deterministic จะทำให้ CI แดงสุ่ม
แล้วคนจะเลิกเชื่อ CI ซึ่งอันตรายกว่าไม่มี CI

| ต้องทำ | ห้ามทำ |
|--------|--------|
| เรียงไฟล์ schema ด้วย `sorted()` | พึ่งลำดับจาก `os.listdir()` |
| เรียง key/field ด้วยลำดับที่กำหนดเอง (ลำดับใน `required` ก่อน แล้วที่เหลือเรียง a-z) | พึ่งลำดับ `dict` จาก `json.load` |
| ขึ้นบรรทัดด้วย `\n` เท่านั้น | ปล่อยให้ Windows เขียน `\r\n` |
| pin เวอร์ชัน `==` | `>=` หรือไม่ pin |
| — | ใส่ timestamp / ชื่อเครื่อง / path เต็มในหัวไฟล์ |

### 4.2 การ map `required` / `null` / ไม่มี field — 3 สถานะที่ต่างกัน

| JSON ที่ได้รับ | `x_present` | `x_is_null` | `x` |
|----------------|-------------|-------------|-----|
| `"sl": 1.08010` | true | false | 1.08010 |
| `"sl": null` | true | true | 0.0 (ห้ามใช้) |
| ไม่มี key `sl` | **false** | false | 0.0 (ห้ามใช้) |

- field ที่อยู่ใน `required` → parser **fail** ถ้า `x_present == false`
- field ที่ไม่อยู่ใน `required` → `x_present == false` เป็นเรื่องปกติ
- `x_is_null == true` → **ห้ามอ่านค่า `x`** (ไม่มีความหมาย)

### 4.3 `ts_utc` เป็น `str` ทั้งสองฝั่ง ไม่แปลงเป็น datetime อัตโนมัติ

**เหตุผล:** pydantic ที่ประกาศเป็น `datetime` จะ**รับ `+07:00` แล้วแปลงให้เงียบๆ**
→ กฎ "UTC ลงท้าย `Z` เท่านั้น" ที่บังคับด้วย `pattern` ใน schema จะหายไป
เพราะ `pattern` ใช้กับ `str` ไม่ใช้กับ `datetime`

แปลงเมื่อจำเป็นผ่าน `brain/common/wiretime.py` (เขียนมือ อยู่นอก `gen/`):
```python
def parse_utc(s: str) -> datetime      # ต้อง raise ถ้าไม่ลงท้าย Z
def format_utc(dt: datetime) -> str    # ต้องออก ...Z เสมอ · ห้ามออก +00:00
```

### 4.4 การ serialize ตัวเลขใน MQL5 — จุดที่พลาดง่ายสุด

| ปัญหา | ต้องทำ |
|-------|--------|
| `DoubleToString(1.08234)` → `"1.08234000"` | ตัดเลข 0 ท้ายทิ้ง แต่**เก็บอย่างน้อย 1 ตำแหน่ง** (`1.0` ไม่ใช่ `1.`) |
| ราคาถูกปัดจนเสียนัยสำคัญ | ใช้ `digits` ของ symbol เมื่อรู้ · ไม่รู้ใช้ **8 ตำแหน่ง** แล้วตัด 0 |
| ค่ามาก/น้อยกลายเป็น `1e-05` | **ห้ามมี `e`/`E` ใน output** — JSON รับได้แต่ฝั่งอื่นอ่านยาก และ MQL5 parse กลับพลาด |
| `point` = `0.00001` | ต้องออก `0.00001` ไม่ใช่ `1e-05` |
| `long` ถูกแปลงผ่าน `double` | `ticket` ต้องใช้ `IntegerToString` เท่านั้น — ผ่าน `double` จะเสียความละเอียดเกิน 2⁵³ |
| `null` ถูกเขียนเป็น `0` | `x_is_null` → เขียน `null` ตัวอักษร |

### 4.5 การ escape string

ต้อง escape: `"` → `\"` · `\` → `\\` · และ control char `0x00–0x1F` → `\uXXXX`
(`\n` `\r` `\t` `\b` `\f` ใช้รูปย่อได้)

**ห้าม escape ตัวอักษรไทย/UTF-8 เป็น `\uXXXX`** — ส่งเป็น UTF-8 byte ตรงๆ
([§1](../02-contracts.md) กำหนด UTF-8) และตอนแปลง string → byte ต้องใช้ `CP_UTF8`
ไม่ใช่ codepage ของเครื่อง (บทเรียนจาก [compile-gate-02](../reviews/SPEC-001-compile-gate-02.md))

### 4.6 `$comment` ต้องถูก emit เป็น comment ในโค้ดที่ generate

ทุก `$comment` ใน schema (invariant ข้ามฟิลด์) ต้องปรากฏเหนือ struct/class ที่เกี่ยวข้อง

```mql5
// INVARIANT (ต้อง validate ในโค้ด schema จับให้ไม่ได้):
//   low <= open <= high · low <= close <= high
//   spread_points_avg <= spread_points_max
struct FarmBarPayload { ... };
```

เหตุผล: invariant พวกนี้ยังไม่มีใคร implement (SPEC-005) — ถ้าไม่โผล่ตรงที่คนเขียนโค้ดเห็น
มันจะถูกลืม แล้วเราจะได้ระบบที่ "schema ผ่าน" แต่ข้อมูลไม่สมเหตุสมผล

### 4.7 พฤติกรรม parser

| สถานการณ์ | ต้องได้ |
|-----------|---------|
| JSON ถูกต้องครบ | `true` · struct เต็ม |
| มี field แปลกปลอม | **`true`** · ข้าม field นั้น (forward compat) |
| ขาด field ที่ `required` | `false` · `FarmLastParseError()` บอก**ชื่อ field ที่ขาด** |
| ชนิดผิด (`"volume": "abc"`) | `false` · error บอกชื่อ field + ชนิดที่คาด |
| enum ค่าที่ไม่รู้จัก | `false` **ยกเว้น** `envelope.type` ที่ต้องได้ `FARM_MSG_UNKNOWN` + `true` |
| JSON พังทั้งก้อน | `false` · error บอกตำแหน่ง |
| ลึกเกิน 32 ชั้น | `false` · error `DEPTH_LIMIT` |
| array ว่าง `[]` / object ว่าง `{}` | `true` · `Size()==0` |

## 5. Edge cases

1. **frame 64 KB vs `positions[]`** — schema จำกัด `maxItems: 64` แล้ว (แก้จาก 512 เพราะ
   512 ไม้ ≈ 128 KB ส่งไม่ได้) · ต้องมี test ว่า STATE ที่เต็มเพดาน **ยังต่ำกว่า 64 KB**
   ถ้าเกิน → รายงานใน implementation note **ห้ามแก้ schema เอง**
2. **`ticket` 64-bit** — `IntegerToString` เท่านั้น · ฝั่ง Python เป็น `int` ไม่ใช่ `float`
3. **`comment` ยาว 31 ตัว** — MQL5 ตัดให้เอง · serializer ต้องไม่ยาวเกินตอนสร้าง
4. **UTF-8 ไทยใน `comment`** — 1 ตัว = 3 byte · `maxLength: 31` ใน schema นับ**ตัวอักษร**
   แต่ MT5 นับ**ตัวอักษร**เหมือนกัน → ok แต่ตอนนับ 64 KB ต้องนับ **byte**
5. **`propertyNames` ใน `volume_map`** — pydantic/datamodel-codegen มัก**ไม่บังคับ** pattern ของ key
   → ต้อง validate เพิ่มเองใน SPEC-005 · ticket นี้แค่รายงานว่า generator ทำได้/ไม่ได้
6. **`oneOf` ที่ใช้กับ nullable + `$ref`** (`assigned_session_id`, `halt_reason` ฯลฯ)
   generator ต้องรู้จักรูปแบบ `oneOf: [<ref|enum>, {type: null}]` = optional ของชนิดนั้น
   **ห้ามสร้าง union class แยก**
7. **`enum` ที่มี `null` อยู่ใน list** (`news_state`) — ต้องกลายเป็น optional enum
8. **schema ใหม่ถูกเพิ่มแต่ไม่ regenerate** — `codegen-check` ต้องจับได้ (test §7 ข้อ 2)
9. **`Free()` ไม่ครบ** → memory leak ใน EA ที่รัน 24/7
10. **รัน codegen บน Windows** — output ต้องเป็น LF (มี `.gitattributes` แล้ว แต่ generator
    ต้องเขียน `\n` เอง ไม่พึ่ง text mode)
11. ★ **C4 — `double` ที่เป็นจำนวนเต็มพอดี** (`contract_size: 100000`) → **ต้องออก `100000.0`**
    · **ตัดสินแล้ว ไม่ใช่ "เลือกอย่างใดอย่างหนึ่ง"** เพราะ §4.4 บังคับอยู่แล้วว่าต้องเหลือทศนิยม
    อย่างน้อย 1 ตำแหน่ง — และ round-trip เป็นการเทียบ **ข้ามภาษา** ไม่ใช่แค่ภายในภาษาเดียว
    · ฝั่ง Python `json.dumps(100000.0)` ให้ `100000.0` อยู่แล้ว → **ตรงกันโดยไม่ต้องทำอะไรเพิ่ม**
    · ตรงข้าม ถ้าเลือก `100000` ฝั่ง MQL5 จะขัด §4.4 ทันที
    · ⚠️ `integer` ใน schema (เช่น `ticket`) **ห้ามมี `.0`** — ออกเป็นจำนวนเต็มล้วนเสมอ
12. **key ซ้ำใน JSON** (`{"a":1,"a":2}`) — parser ต้องรับได้ (ใช้ค่าหลังสุด) ไม่ crash
