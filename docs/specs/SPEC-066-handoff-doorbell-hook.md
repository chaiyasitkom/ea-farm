## 1. Goal

เมื่อ push ที่มีไฟล์ใหม่ใน `handoff/` → ส่ง Telegram บอกว่า**มีของรอ** เพื่อให้เจ้าของ
รู้ว่าถึงคิวเปิด session ไหน โดยไม่ต้องคอยเช็คกล่องเอง

## 2. Non-goals

- ❌ **ห้ามส่งเนื้อหาข้อความ** — ส่งแค่ metadata ([SPEC-029 §4.2.1](SPEC-029-telegram-alerting.md) อธิบายเหตุผล 4 ข้อ)
- ❌ ห้าม retry / queue / persist — ถ้าส่งไม่ได้ก็แล้วไป (SPEC-029 ค่อยทำให้ถูก)
- ❌ ห้ามแตะ `brain/**` — ห้าม import อะไรจากโปรเจกต์
- ❌ ห้ามอ่านหรือส่งเนื้อไฟล์ · ห้ามส่ง path เต็มของเครื่อง

## 3. Interface

| ไฟล์ | ทำอะไร |
|------|--------|
| `tools/hooks/pre-push` | **สร้าง** — sh script (Git Bash) |
| `tools/install-hooks.ps1` | **สร้าง** — คัดลอกเข้า `.git/hooks/` + `chmod +x` |
| `.env.example` | **แก้** — เพิ่ม `HANDOFF_BELL_TOKEN` · `HANDOFF_BELL_CHAT_ID` |

**hook ไม่ถูก version ควบคุม** (`.git/hooks/` ไม่อยู่ใน repo) → ต้องมีตัวติดตั้ง
· `install-hooks.ps1` ต้อง **idempotent** รันซ้ำได้

### 3.1 ★★ ที่เก็บ token — ห้ามอยู่ในรีโป

อ่านจาก **`%USERPROFILE%\.ea-farm-bell`** (ไม่ใช่ `.env` ของโปรเจกต์)

```
HANDOFF_BELL_TOKEN=...
HANDOFF_BELL_CHAT_ID=...
```

| เหตุผล | |
|--------|---|
| อยู่นอก repo | ไม่มีทางเผลอ commit แม้ `.gitignore` พัง |
| แยกจาก `.env` ของ SPEC-002 | ของชั่วคราวไม่ควรไปปนกับ config ถาวร ลบทิ้งง่าย |
| ไม่มีไฟล์ = **เงียบ ไม่ error** | คนที่ไม่ได้ตั้งค่ายังต้อง push ได้ตามปกติ |

## 4. Behaviour

### 4.1 ★★ กฎเหล็ก: **ห้ามบล็อก push ไม่ว่ากรณีใด**

```sh
exit 0    # ← ทุกเส้นทางออกของ hook ต้องเป็น 0
```

| สถานการณ์ | ต้องทำ |
|-----------|--------|
| ไม่มีไฟล์ token | เงียบ · `exit 0` |
| ไม่มีเน็ต / Telegram ตอบ error | log บรรทัดเดียวลง stderr · `exit 0` |
| `curl` ไม่มีในเครื่อง | เงียบ · `exit 0` |
| script ตัวเองพัง | **`trap` แล้ว `exit 0`** |

**เหตุผล:** นี่คือกริ่ง ไม่ใช่ gate · กริ่งที่ทำให้ push ไม่ได้คือกริ่งที่จะถูกถอดทิ้งภายในวันเดียว
· ตั้ง `curl --max-time 5` ด้วย ไม่งั้นเน็ตช้าจะหน่วงทุก push

### 4.2 ตรวจว่ามีอะไรต้องบอกไหม

`pre-push` รับ `<local_ref> <local_sha> <remote_ref> <remote_sha>` ทาง **stdin**

```sh
git diff --name-status --diff-filter=A "$remote_sha".."$local_sha" -- handoff/
```

| เงื่อนไข | ผล |
|----------|-----|
| ไม่มีไฟล์ **เพิ่มใหม่** ใน `handoff/` | เงียบ · `exit 0` |
| `remote_sha` เป็น `000…0` (branch ใหม่) | ใช้ `git diff` กับ merge-base ของ `main` แทน · ถ้าหาไม่ได้ให้เงียบ |
| มีไฟล์ใหม่ | ส่ง §4.3 |

**นับเฉพาะไฟล์ที่ `A` (เพิ่มใหม่)** — แก้ข้อความเดิมไม่ต้องตีกริ่ง
· ไฟล์ใน `archive/` ไม่นับ (ปิดเรื่องแล้ว)

### 4.3 ข้อความ

อ่าน **frontmatter เท่านั้น** — `id` · `from` · `ticket` · `type` · `blocking`

```
📮 handoff · 1 ใหม่
to-claude/002-w1-socketsend.md
type=handoff ticket=SPEC-016 blocking=false
```

`blocking: true` แม้ตัวเดียว → ขึ้นต้นด้วย `🔴 BLOCKING` แทน `📮`

| กฎ | |
|----|---|
| **ห้ามใส่บรรทัดใดจากเนื้อข้อความ** | §2 |
| ส่งเป็น plain text **ไม่ตั้ง `parse_mode`** | ชื่อไฟล์มี `_` และ `-` เยอะ · [SPEC-029 §4.4](SPEC-029-telegram-alerting.md) |
| มากกว่า 5 ไฟล์ → สรุปเป็น `📮 handoff · N ใหม่` + ชื่อ 3 ตัวแรก + `…` | กัน push ใหญ่ทำข้อความยาว |

### 4.4 ยอมรับตรงๆ ว่ากริ่งนี้อาจตีก่อนของถึง

`pre-push` ทำงาน **ก่อน** push สำเร็จ → ถ้า push ถูกปฏิเสธ (non-fast-forward · เน็ตหลุด)
**กริ่งดังไปแล้วแต่ของยังไม่ถึง remote**

| ทางเลือก | ทำไมไม่เอา |
|----------|------------|
| verify แล้วค่อยส่ง (fork background) | git hook + background process บน Windows เปราะ · ได้ความซับซ้อนแลกกับกรณีที่เกิดไม่บ่อย |
| ใช้ `post-commit` แทน | ยิ่งผิด — commit แล้วแต่ยังไม่ push อีกฝ่ายก็ยังไม่เห็น |

**ตัดสิน: ยอมให้ตีก่อน** และเขียนกำกับไว้ในข้อความว่ามาจาก `pre-push`
· ผลเสียสูงสุดคือเปิด session มาแล้วกล่องว่าง — เสียเวลา 10 วินาที
· **แต่ต้องเขียนข้อจำกัดนี้ไว้ในหัวไฟล์ hook** ห้ามให้คนรุ่นหลังคิดว่ามันการันตี

> ตรงข้ามกับ gate ที่ผมยืนกรานว่าห้ามรายงานผลที่ไม่ได้ตรวจ —
> **ต่างกันตรงผลของการผิด**: gate ผิด = ปล่อยโค้ดเสียผ่าน · กริ่งผิด = เดินไปดูแล้วไม่มีอะไร

## 5. Edge cases

1. **push หลาย branch พร้อมกัน** — stdin มีหลายบรรทัด → รวมไฟล์ทุก ref แล้วส่ง**ข้อความเดียว**
2. **push แล้วไม่มี commit ใหม่** (`up to date`) — hook ไม่ถูกเรียก ✅
3. **ชื่อไฟล์มีอักขระ non-ASCII** — ส่งเป็น UTF-8 ตรงๆ · **ห้าม escape**
4. **frontmatter หาย/ผิดรูป** — ส่งชื่อไฟล์อย่างเดียว `type=? blocking=?` · **ห้าม crash**
5. **`git push --delete` / push tag** — ไม่มีไฟล์ใหม่ใน `handoff/` → เงียบ
6. **hook ถูกเรียกตอน rebase/amend** — ใช้ diff ของ sha จริงเสมอ ไม่ใช่ `HEAD~1`

## 6. Acceptance criteria

- [ ] ★★ **ลบไฟล์ token ทิ้ง → `git push` ยังทำงานปกติ ไม่มี error**
- [ ] ★★ **ตัดเน็ตแล้ว push → สำเร็จตามปกติ** · หน่วงไม่เกิน ~5 วินาที
- [ ] ★★ `grep -c "exit [^0]" tools/hooks/pre-push` = **0** (ยกเว้นใน comment)
- [ ] push ที่ไม่แตะ `handoff/` → **ไม่ส่งอะไรเลย**
- [ ] push ไฟล์ใหม่ 1 ตัว → ได้ข้อความมี ชื่อไฟล์ · `type` · `ticket` · `blocking`
- [ ] `blocking: true` → ข้อความขึ้นต้น `🔴 BLOCKING`
- [ ] push 8 ไฟล์ → สรุป ไม่ยาวเกิน
- [ ] ★ **ไม่มีบรรทัดใดจากเนื้อข้อความอยู่ในสิ่งที่ส่ง** — ตรวจด้วยการใส่คำ `CANARY_DO_NOT_SEND`
      ในเนื้อไฟล์ทดสอบ แล้วยืนยันว่าไม่โผล่
- [ ] `install-hooks.ps1` รันซ้ำได้ · แจ้งชัดถ้ามี hook เดิมอยู่แล้ว
- [ ] หัวไฟล์ hook มี `# TEMPORARY — ลบเมื่อ SPEC-029 §4.2.1 ใช้งานได้`
      และข้อจำกัด §4.4
- [ ] `grep -rn "HANDOFF_BELL_TOKEN" .` — เจอเฉพาะใน `.env.example` และ spec นี้ **ไม่มีค่าจริง**
