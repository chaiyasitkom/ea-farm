# ADR-005 — ห้าม hedge ข้ามบัญชีทั้งฟาร์ม (ปิด D10)

**สถานะ:** ACCEPTED · **วันที่:** 2026-07-30 · **ตัดสินโดย:** เจ้าของโปรเจกต์
**ปิด:** [D10](../backlog.md) · **กระทบ:** SPEC-024 · SPEC-025 (P12) · SPEC-026 · [03-risk-spec §L2](../03-risk-spec.md)
**ต่อยอดจาก:** [ADR-001 §2](ADR-001-hedging-account.md) (R18 ระดับบัญชี) · [ADR-003 §4](ADR-003-multi-broker.md) (ตั้งคำถาม)

---

## 1. การตัดสิน

**ห้ามถือ exposure สวนทางกันใน canonical symbol เดียวกัน — ทั้งฟาร์ม ข้ามบัญชี ข้ามโบรกเกอร์ ข้ามกลยุทธ์**

| | |
|---|---|
| กฎใหม่ | **P12 `no_cross_account_hedge`** ในชั้น L2 |
| การบังคับใช้ | **reject intent** ที่จะทำให้เกิดสภาพสวนทาง (ไม่ใช่แค่ alert) |
| การนับ exposure | P3/P4 รวม exposure ของ canonical symbol เดียวกันแบบ **gross** ห้าม net หักกัน |
| ระดับที่ตรวจ | brain (L2) เท่านั้น — EA เห็นบัญชีเดียว ตรวจไม่ได้โดยหลักการ (§4) |

R18 ([ADR-001](ADR-001-hedging-account.md)) ยังอยู่เหมือนเดิมและกันคนละชั้น:

```
R18  (L1, EA)    ห้าม long+short พร้อมกันใน (magic, symbol) ของบัญชีเดียว
P12  (L2, brain) ห้าม long+short พร้อมกันใน canonical symbol เดียวกันทั้งฟาร์ม
```

**"แยกบัญชี" ไม่ได้แปลว่า "สวนกันได้อีกต่อไป"** — [ADR-001 §ทางเลือกที่ไม่เอา](ADR-001-hedging-account.md)
เคยบอกว่า *"ถ้าอยากให้กลยุทธ์สวนกันได้ ให้แยกบัญชี"* ตอนนั้นฟาร์มมีบัญชีเดียวจึงไม่มีผลจริง
· ตอนนี้มีหลายบัญชีจริงแล้ว ประโยคนั้นจึงถูก **ยกเลิก** ด้วย ADR ฉบับนี้

## 2. นิยามที่ผูกพัน — "สวนทางกัน" คืออะไรเป๊ะๆ

```
farm_net(c) = Σ owned_net ของ canonical symbol c  ทุกบัญชี ทุกโบรกเกอร์
              (แปลง raw → canonical ด้วย SPEC-064 ก่อนเสมอ)

มี hedge ข้ามบัญชีเมื่อ:  ∃ บัญชี a, b (a ≠ b) ที่  net_a(c) > 0  และ  net_b(c) < 0
```

**ห้ามตัดสินจาก `farm_net(c)`** — `+0.10` กับ `−0.10` ให้ `farm_net = 0` ซึ่งอ่านว่า "ไม่มีอะไรเลย"
ทั้งที่คือเคสที่กฎนี้มีไว้จับพอดี · ต้องดูรายบัญชีเสมอ

### 2.1 intent แบบไหนถูก reject

| สถานะฟาร์มตอนนี้ (canonical `EURUSD`) | intent ใหม่ | ผล |
|---|---|---|
| บัญชี A `+0.10` | บัญชี B ขอ `−0.05` | ❌ **reject** `P12_CROSS_ACCOUNT_HEDGE` |
| บัญชี A `+0.10` | บัญชี A ขอ `−0.05` | ❌ reject — R18 จับที่ EA อยู่แล้ว (กลับข้าง §4.5 SPEC-027) |
| บัญชี A `+0.10` | บัญชี B ขอ `+0.05` | ✅ ผ่าน (ถ้า P3/P4 ยอม) |
| บัญชี A `+0.10` · B `−0.05` (สภาพที่ไม่ควรเกิด) | A ขอ `+0.02` | ❌ reject — ห้ามขยายสภาพที่ผิดอยู่แล้ว |
| บัญชี A `+0.10` · B `−0.05` | B ขอ `0` (ปิด) | ✅ **ต้องผ่านเสมอ** |
| บัญชี A `+0.10` · B `−0.05` | A ขอ `+0.05` (ลดลง) | ✅ ผ่าน — เดินเข้าหาสภาพที่ถูกต้อง |

**หลักการที่ครอบทุกแถว:** intent ที่ทำให้ค่า `Σ|net_i(c)|` (gross) **ลดลงหรือเท่าเดิม** ผ่านได้เสมอ
· intent ที่ทำให้เพิ่มขึ้นในขณะที่มีสภาพสวนทางอยู่ = reject
**ความสามารถในการปิดไม้ต้องไม่ถูกกฎที่ตั้งใจลดความเสี่ยงปิดกั้น** — หลักการเดียวกับ
[SPEC-027 §4.5](../specs/SPEC-027-risk-directive.md) และ [SPEC-023](../specs/SPEC-023-safemode.md)

### 2.2 ★ ต้องนับ intent ที่ยังไม่ยืนยันด้วย ไม่ใช่แค่ position ที่มีจริง

`STATE` มาทุก 5 วินาที · intent สองใบไปคนละบัญชีในช่วงเวลาเดียวกันจะเห็นภาพเก่าทั้งคู่
แล้ว**สร้าง hedge พร้อมกันโดยที่แต่ละใบผ่านการตรวจ**

```
effective_net(a, c) = net จาก STATE ล่าสุดของบัญชี a
                    + Σ delta ของ intent ที่ส่งไปแล้วแต่ยังไม่ได้ EXEC_REPORT/STATE ยืนยัน
```

- การประเมิน P12 ต้อง **serialize ต่อ canonical symbol** (ประเมินทีละใบ ไม่ใช่ขนาน)
- intent ที่ยังไม่ยืนยันเกิน `intent_timeout` ให้ถือว่า **ยังค้างอยู่** (fail-closed)
  จนกว่าจะมี `INTENT_ACK REJECTED` หรือ `STATE` ที่พิสูจน์ว่าไม่เกิด —
  ตรงกับ intent cache ของ [SPEC-012](../specs/SPEC-012-intent-cache.md)

## 3. สภาพสวนทางที่ **เกิดขึ้นแล้ว** — ไม่ปิดอัตโนมัติ

P12 กันไม่ให้เกิดใหม่ แต่ยังเกิดได้จาก: เทรดมือ · ไม้ค้างจากก่อนติดตั้งกฎ · race ที่หลุด ·
บัญชีที่ heartbeat หายไปแล้วกลับมาพร้อมไม้ที่ไม่รู้จัก

| ทางเลือก | ผล |
|----------|-----|
| ปิดขาใดขาหนึ่งอัตโนมัติ | ❌ ระบบต้องเลือกว่าปิดขาไหน = **ตัดสินใจเทรดแทนคน** โดยไม่มีข้อมูลว่าขาไหนถูก · และถ้าปิดพลาดจะเหลือ exposure เปิดโล่งด้านเดียว |
| ปล่อยผ่าน alert อย่างเดียว | ❌ สภาพนี้ทำให้ P3/P4 อ่านค่าผิดทั้งระบบ |
| ✅ **`REDUCE_ONLY` เฉพาะ canonical นั้น + alert ERROR + ค้างไว้จนคนแก้** | หยุดไม่ให้แย่ลง · ยังปิดไม้ได้ · คนเป็นคนตัดสินว่าปิดขาไหน |

- alert `P12_HEDGE_STATE_DETECTED` severity **ERROR** ส่งซ้ำทุกครั้งที่ยังพบ (ไม่ใช่ครั้งเดียวแล้วเงียบ)
- ขึ้น dashboard เป็นแถวแดงค้าง ([SPEC-028](../specs/SPEC-028-dashboard-kill-switch.md)) พร้อมชื่อบัญชีทั้งสองขา
- **ระหว่างนี้ P3/P4 ต้องนับแบบ gross** (§5) — ตัวเลขจะพุ่งขึ้น ไม่ใช่ดูสงบลง

## 4. ช่องว่างที่ยอมรับไว้อย่างเปิดเผย: brain ตาย

P12 อยู่ชั้น L2 เท่านั้น เพราะ EA แต่ละตัวเห็นบัญชีเดียว — จะบังคับที่ L1 ต้องให้ EA รู้สถานะทั้งฟาร์ม
ซึ่งขัดหลัก *"L1 ต้องทำงานได้แม้ brain ตาย"* (ต้องพึ่ง brain ถึงจะรู้)

**แต่ช่องว่างนี้ปิดโดยกฎที่มีอยู่แล้ว:** brain เงียบ > 10s → R16 SafeMode → EA ไม่รับ intent ใหม่
และไม่มีใครสร้าง intent ได้เลยเพราะ brain คือคนสร้าง

```
brain ตาย  →  ไม่มี intent ใหม่  →  สร้าง hedge ใหม่ไม่ได้
```

เหลือความเสี่ยงจริงเพียงกรณีเดียว: **มนุษย์เทรดมือระหว่าง brain ตาย** — ครอบด้วย R19
`foreign_position_alert` และเป็นเรื่องวินัยการใช้งาน ไม่ใช่สิ่งที่โค้ดกันได้

## 5. ผลต่อการนับ exposure — gross ที่ระดับ symbol, signed ที่ระดับสกุลเงิน

| ระดับ | วิธีรวม | เหตุผล |
|-------|---------|--------|
| canonical symbol (P12 · P4) | **gross** `Σ|risk_pct_i|` | hedge ต้องไม่ทำให้ตัวเลขความเสี่ยงลดลง — จ่าย spread+swap 2 ขาแล้วยังกินมาร์จิ้น 2 ขา |
| สกุลเงิน (P3) | **signed** | long `EURUSD` + short `EURGBP` หัก EUR กันจริงในเชิงเศรษฐกิจ ([ADR-004 §2.3](ADR-004-exposure-unit.md)) |

ความต่างนี้ **ตั้งใจ** — `hedge symbol เดียวกันคนละบัญชี` เป็นการหลอกตัวเลข
ส่วน `หักล้างสกุลผ่านคู่คนละคู่` เป็นการลดความเสี่ยงจริง

## 6. ทางเลือกที่พิจารณาแล้วไม่เอา

| ทางเลือก | ทำไมไม่เอา |
|----------|-----------|
| **แยกบัญชี = อนุญาตให้สวนกัน** (คนละกลยุทธ์สวนกันได้) | ต้นทุนจริงคือ spread 2 ขา + swap 2 ขา + margin 2 ขา เพื่อ exposure สุทธิ 0 · ถ้าสองกลยุทธ์เห็นตรงข้ามกัน คำตอบที่ถูกคือ **ไม่เข้าไม้** ไม่ใช่เข้าทั้งสองข้าง · และถึงยอมให้เกิด P3/P4 ก็ยังต้องนับ gross อยู่ดี = ได้ความซับซ้อนโดยไม่ได้อิสระเพิ่มจริง |
| **ห้าม default + whitelist คู่กลยุทธ์ที่สวนกันได้** | เพิ่ม config surface ในชั้นที่เงินหาย · ต้องมี test ของ path ที่ยังไม่มีใครใช้ · **ยังไม่มีกลยุทธ์ที่ต้องการมันแม้แต่ตัวเดียว** — เปิด ticket ใหม่ตอนที่มีของจริง ง่ายกว่าถอดออกทีหลัง |
| **alert อย่างเดียว ไม่ reject** | ตัวเลข P3/P4 เพี้ยนทั้งระบบระหว่างที่ยังไม่มีคนมาอ่าน alert |
| **บังคับที่ L1 (EA)** | EA เห็นบัญชีเดียว · จะทำได้ต้องให้ EA พึ่ง brain = ทำลายหลักการของ L1 (§4) |
