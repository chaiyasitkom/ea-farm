# 2 ข้อที่เหลือ — **ทั้งคู่เป็นปัญหาของ test ไม่ใช่ของ EA**

`test_backoff_schedule_matches_spec` ล้มด้วย `16.844 not <= 1.5` · ข้อมูลจริง:

```
connect ทั้งหมด 7 ครั้ง
  gap 1 = 16.84s   ← ★ ผิดปกติ
  gap 2 =  1.00s ┐
  gap 3 =  2.00s │
  gap 4 =  5.00s ├── ladder เริ่มใหม่ที่ 1 อย่างถูกต้อง
  gap 5 =  9.00s │
  gap 6 = 14.98s ┘
คาดหวัง: 1, 2, 4, 8, 16, 30
```

## T1 🟠 มี `connect` ค้างจาก terminal รอบก่อน → การจับคู่เลื่อนไปหนึ่งช่อง

`gap 1 = 16.84s` แล้ว `gap 2` เริ่มที่ `1.00s` พอดี → **ladder เริ่มใหม่ถูกต้องที่ connect ตัวที่ 2**
· connect ตัวแรกจึงเป็นของ **terminal รอบก่อนที่ยังปิดไม่สนิท** ตอน test นี้เริ่ม

`live_terminal` ทำ `terminate()` → `kill()` ใน `finally` **แต่ไม่รอให้ process ตายจริง**
ก่อนที่ test ถัดไปจะเริ่ม → EA ตัวเก่ายิง connect ทิ้งท้ายได้อีก 1 ครั้ง

**แก้:** หลัง kill ต้อง **รอจนไม่มี `terminal64.exe` เหลือ** ก่อนคืนจาก context manager
· `assert_no_terminal_running()` มีอยู่แล้วตอน**เริ่ม** — ต้องมีตอน**จบ**ด้วย

> เป็นญาติกับ **W3** — state จากรอบก่อนรั่วมารอบถัดไปแล้วทำให้ผลเชื่อไม่ได้
> · ครั้งนี้เป็น process ไม่ใช่ไฟล์

## T2 🟠 tolerance ไม่ได้เผื่อ granularity ของ timer (= F2 เดิม)

ดูจาก gap 2–6: **1, 2, 5, 9, 15** เทียบกับที่คาด **1, 2, 4, 8, 16**

| ขั้น | คาด | ได้ | ต่าง |
|------|-----|-----|------|
| 3 | 4 | **5** | +1 |
| 4 | 8 | **9** | +1 |
| 5 | 16 | **15** | −1 (อยู่ในช่วง jitter ±20%) |

**`+1` คงที่คือ `EventSetTimer(1)`** — `Pump()` เดินทุก 1 วินาที การรอ N วินาทีจึงตกได้ใน `[N, N+1]`
**ไม่ใช่บั๊ก เป็นพฤติกรรมที่ถูกต้องตามการออกแบบ**

```python
self.assertLessEqual(observed, nominal * 1.5 + 1.1)   # +1.1 = 1 tick ของ timer
```
