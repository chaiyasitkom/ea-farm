## ★ หลักฐานที่บอกว่าสมมติฐานของ F1 ผิดตั้งแต่ต้น

`ea-farm-live-events-bad-token.jsonl` — timeline จริง:

```
connect      t=139483.88
message      t=139484.89          ← EA ส่ง HELLO (1 วิหลัง connect · deferred hello ทำงานถูก)
hello_ack    t=139484.89  BAD_TOKEN   ← server ตอบ reject ทันที
disconnect   t=139514.89          ← ★ 30.00 วินาทีพอดีหลังจากนั้น
connect      t=139515.89
```

**30.00 วินาทีเป๊ะ = `asyncio.wait_for(readline, timeout=30.0)` ของ `echo_server`**
· และ **ไม่มี `client_closed`** ก่อนหน้า (ต่างจาก `reconnect` ที่มี `client_closed=2`)

→ **server เป็นฝ่ายตัด ไม่ใช่ EA** → **EA ไม่เคยประมวลผล `HELLO_ACK` ใบนั้นเลย**

ถ้า EA อ่านได้ `HandleInboundLine` (`Wire.mqh:570-598`) จะเข้า branch `accepted == false`
→ `CloseSocket()` + `EnterState(WIRE_FAILED_AUTH)` **ทันที** → server ต้องเห็น `client_closed` ในเสี้ยววินาที
· **ไม่มีเงื่อนไข state คุม branch นั้นเลย** ผมตรวจแล้ว — ถ้าบรรทัดถึง handler มันต้องทำงาน

**สรุป: ปัญหาไม่ใช่ "อ่าน buffer ไม่ทันก่อนปิด" (F1) แต่คือ EA ไม่ได้อ่าน inbound เลยหลังส่ง HELLO**

## หลักฐานที่สอง — `heartbeat-gap` บอกเรื่องเดียวกัน

```
connect     t=139581.45
message     t=139582.50
hello_ack   t=139582.50  accepted=True     ← ผ่าน auth แล้ว
disconnect  t=139607.64                    ← 25 วินาทีต่อมา ไม่มีอะไรเกิดขึ้นเลย
```

server ตัวนี้รันด้วย `--no-heartbeat-ack` · EA ควรนับ missed ack แล้ว reconnect
· **ไม่มี `message` เพิ่มอีกเลยหลัง HELLO** = **EA ไม่ได้ส่ง heartbeat ด้วยซ้ำ**

→ ไม่ใช่แค่ "ไม่อ่าน" แต่ **`Pump()` ไม่ได้เดินต่อไปถึงส่วน `WIRE_READY` เลย**

## 🔍 ผู้ต้องสงสัยหลัก — ลำดับใหม่ใน `Pump()`

```mql5
ReadAvailable();                                              // ← ใหม่ ย้ายขึ้นมา

if(m_socket != INVALID_HANDLE && !SocketIsConnected(m_socket))
   ReadAvailable();                                           // ← ใหม่ เรียกซ้ำ

if(m_socket != INVALID_HANDLE && !SocketIsConnected(m_socket))
{ m_log.Warn("socket_disconnected"); CloseSocket(); ScheduleReconnect(); }
```

และใน `ReadAvailable()` คุณเอา guard ออก:

```mql5
-      if(m_socket == INVALID_HANDLE || !SocketIsConnected(m_socket))
+      if(m_socket == INVALID_HANDLE)
```

**สิ่งที่ต้องตรวจก่อนอย่างอื่น:** `SocketIsReadable()` บน MT5 คืนอะไรเมื่อ socket ยังต่ออยู่แต่ไม่มีข้อมูล
· ถ้ามันคืน `true` แล้ว `SocketRead` คืน `0` → `break` ออกจาก loop ทุกครั้ง — ปกติ
· แต่ถ้าคืนค่าที่ทำให้ loop วนนานผิดปกติ `Pump()` จะกินเวลาจนงานอื่นในรอบนั้นไม่ได้เดิน

**ให้วัดก่อนเดา:** log `pump_elapsed_us` กับจำนวนรอบของ `while(SocketIsReadable(...))` ต่อ `Pump()`
· มี `RecordPumpElapsed` + `pump_slow_us` อยู่แล้วที่ `Wire.mqh:869-872` — เอาผลนั้นมาดู
