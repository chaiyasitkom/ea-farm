## งานถัดไป — ข้อ 2 เท่านั้น

เลื่อน `SendHello()` ออกจากรอบที่เพิ่ง `SocketConnect`:

```mql5
// TryConnect() -- จบแค่ตรงนี้ ไม่ส่งต่อ
EnterState(WIRE_CONNECTED);
SocketTimeouts(...); m_log.Info("socket_connected ...");
m_reconnect_count++;
// SendHello();          ← เอาออก

// Pump() -- รอบถัดไปค่อยส่ง
if(m_state == WIRE_CONNECTED)
   SendHello();
```

ต้องมี **timeout ของ state `WIRE_CONNECTED`** ด้วย ไม่งั้นถ้า `SendHello()` ล้มเงียบ
จะค้างใน `WIRE_CONNECTED` ตลอดกาลโดยไม่มีใคร reconnect ให้
(ตอนนี้มี timeout เฉพาะ `WIRE_AUTHENTICATING` ที่ `Wire.mqh:848`)

## 🔍 เจอเพิ่มระหว่างอ่าน log — ตรวจให้หน่อย

```
INFO ... socket_connected host=127.0.0.1  port=45001
                                        ↑↑ ช่องว่าง 2 ตัว
```

format string คือ `"socket_connected host=%s port=%d"` ซึ่งมีช่องว่างตัวเดียว
→ **`m_host` มีอักขระเกินท้ายสตริง** เกือบแน่นอนคือ `\r` จากไฟล์ `.set` ที่เขียนด้วย `\r\n`
(`live_mt5_harness.py:161` ใช้ `"\r\n".join(...)`)

**ยังไม่ใช่สาเหตุของ W1** เพราะ connect สำเร็จ (server accept ได้) **แต่ตรวจให้แน่**:

| input | ถ้ามี `\r` ติดมาจะเกิดอะไร |
|-------|---------------------------|
| `InpBrainHost` | connect ยังผ่าน (ตัวแยกชื่อโฮสต์ยอม) |
| ★ **`InpBrainToken`** | **token จะไม่ตรงกับที่ server คาดไว้ → HELLO ถูก reject** |
| `InpMagic` · `InpHeartbeatSec` | `StringToInteger` ตัดให้ อาจไม่มีปัญหา |

→ log ความยาวของ `m_host` และ `m_token` ตอน `Init()` (**อย่า log ค่า token**)
ถ้าเกินที่ควรเป็น 1 ตัว = ยืนยัน · แก้ที่ trim input ตอนอ่าน **ไม่ใช่แก้ที่ harness**
เพราะ `.set` ของจริงตอน deploy ก็อาจเป็น CRLF เหมือนกัน

> ข้อนี้เป็นหนี้ที่รอระเบิดตอน SPEC-013 (gateway ตรวจ token จริง) —
> ตอนนี้ `echo_server` ไม่ได้ตรวจเข้ม เลยยังไม่เห็น
