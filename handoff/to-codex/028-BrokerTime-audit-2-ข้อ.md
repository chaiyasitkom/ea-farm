# `BrokerTime.mqh` audit — **2 ข้อต้องแก้** (ไม่ด่วน · อย่าแทรกก่อน B2/A2)

ไฟล์นี้ `APPROVED_WITH_NOTES` ไปแล้วรอบ 4 และไม่มีใครแตะอีก
ผมไล่ทั้งไฟล์แบบเดียวกับ `Wire.mqh` · เต็ม: [SPEC-063-timing-audit.md](../../docs/reviews/SPEC-063-timing-audit.md)

> ### ★ ข้อสรุป: **B16b ถูกแก้ที่อาการ ไม่ใช่ที่ต้นเหตุ**
>
> การ cast เป็น `long` **ถูกต้องและจำเป็น** — แต่ต้นเหตุจริงคือ
> *"ใช้นาฬิกาผนังวัดระยะเวลา"* ซึ่ง **ยังอยู่ครบทั้ง 2 จุด**
> `long` แค่เปลี่ยนผลจาก "บวกมหาศาล" เป็น "ติดลบ" — **ยังผิดอยู่ แค่ผิดคนละแบบ**

## 🔴 B-A1 — `Refresh()` throttle ใช้นาฬิกาที่ตัวเองกำลังตรวจสอบ

```mql5
const long gmt_now = (long)m_src.GmtTime();                        // BrokerTime.mqh:166
if(m_last_sample_gmt > 0 && gmt_now > 0 && gmt_now - m_last_sample_gmt < 20)
   return false;                                                    // :170
```

**นาฬิกาถอยหลัง 1 ชั่วโมง → ผลต่างติดลบ → `< 20` จริง → `Refresh()` ตายไป 1 ชั่วโมง**

`FarmExecutor.mq5:92` เรียกทุก 1 วินาที และ **การคืน `true` คือทางเดียว**
ที่ `BROKER_TIME_OFFSET_CHANGED` จะถูก log/ส่งออก → ช่วงตาบอดนั้น
**offset เปลี่ยนโดยไม่มีใครรู้ · เส้นแบ่งวัน R6 ขยับทั้งระบบเงียบๆ**

**และนาฬิกากระโดดตอน DST พอดี** — คือเหตุการณ์เดียวที่โมดูลนี้มีไว้จับ

```mql5
uint now_tick = GetTickCount();
if(m_last_sample_tick != 0 && (int)(now_tick - m_last_sample_tick) < 20000)
   return false;
```

**cast signed ก่อนเทียบเสมอ** — สำนวนเดียวกับ **S1(d)** และ **S5**

## 🔴 B-A2 — หน้าต่าง 90 วินาทีใช้นาฬิกาผนังเดียวกัน · **fail-open ได้**

```mql5
if(gmt_now - m_bad_sample_started_gmt > 90)     // :97
```

| นาฬิกา | ผล |
|--------|-----|
| กระโดดหน้า ระหว่างหน้าต่างเปิด | หน้าต่างสั้นลง → invalid เร็วเกินไป |
| **ถอยหลัง** | ผลต่างติดลบ → **ไม่มีวัน `> 90`** → **ค้างที่ `valid` ทั้งที่ sample เสียตลอด** |

เคสที่สองคือ **fail-open** — โมดูลที่ออกแบบให้ fail-closed กลับแจกค่า offset เก่าต่อไปเรื่อยๆ
**อันตรายกว่าการ invalid ผิด**

**แก้:** จับเวลาด้วย tick เดียวกับ B-A1

## ⛔ 5 ข้อที่ผมตรวจแล้วไม่พัง — **ห้ามไปแก้**

| ดูน่าสงสัย | ความจริง |
|-----------|----------|
| `RoundToNearest` สาขาค่าลบ | สมมาตรกับฝั่งบวกเป๊ะ (`-3601`→`-3600` · `-450`→`-900` แล้วโดน guard ตัด) |
| `AcceptOffset` เงื่อนไข 3 ชั้น | call site เดียวที่ `initial=false` ถูกป้อง `if(!m_valid)` อยู่แล้ว → เทียบเท่า `detected != old` ตรงตาม B15 |
| `:207` ใช้ offset ผิดตัว | ถูกแล้ว — `m_last_server` ถูกอ่านภายใต้ระบอบใหม่ |
| `datetime` underflow (B16b) | **ปิดจริง** ไม่เหลือการลบ `datetime` ตรงๆ |
| ขอบเขต `-43200/+50400` | ถูก (−12h…+14h) |

ผมไล่เลขทุกข้อแล้ว · **การ "แก้ไว้ก่อน" จะเพิ่มความซับซ้อนโดยไม่ได้อะไร**
