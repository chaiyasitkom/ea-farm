# หยุดแก้ตรรกะ — ปัญหาจริงตอนนี้คือ **เรามองไม่เห็น**

## ✅ ก่อนอื่น — ผมสรุปผิดใน 008 ขอแก้

**ผมบอกว่า F1 ทำให้ `heartbeat_gap` ถอย — ไม่จริง**

หลัง revert แล้ว `heartbeat_gap` **ยังตกเหมือนเดิม** และ `test_backoff_schedule_matches_spec`
ที่เคยตก **กลับผ่านในรอบนี้** ทั้งที่ไม่มีใครแตะมัน

→ **test สองตัวนี้ flaky** · การเทียบผลระหว่างรอบจึงเชื่อไม่ได้
· **revert ไม่เสียเปล่า** — ทำให้รู้ว่า F1 ไม่ใช่ต้นเหตุ และตัดตัวแปรทิ้งได้จริง

| test | 02:05 | 02:18 (F1) | 02:43 (revert) |
|------|-------|-----------|----------------|
| `reconnect` | ✅ | ✅ | ✅ |
| `backoff` | 🔴 2.0 | ? | ✅ **ผ่าน** |
| `heartbeat_gap` | ✅ | 🔴 | 🔴 |
| `bad_token` | 🔴 32.0 | 🔴 | 🔴 33.1 |
| `duplicate` | 🔴 33.1 | 🔴 33.0 | 🔴 32.0 |

**`bad_token` + `duplicate` ตกทุกรอบด้วยตัวเลขเดิม (32–33s) = บั๊กจริง** · ที่เหลือ flaky

## ★ `pump_diag` ที่คุณใส่ให้ผลทันที — และชี้ว่าติดที่การมองเห็น

```
02:43:55.886  DISCONNECTED -> CONNECTED       read_loops=0  bytes_read=0  pump_elapsed_us=15671
02:43:56.909  CONNECTED    -> AUTHENTICATING  read_loops=0  bytes_read=0  pump_elapsed_us=16869
   ← ไฟล์ log จบตรงนี้
```

| สิ่งที่รู้แล้ว | |
|---|---|
| state machine เดินถูก | `DISCONNECTED → CONNECTED → AUTHENTICATING` ✅ |
| `SocketConnect` ใช้เวลา ~15.7ms · `SendHello` ~16.9ms | ปกติ ไม่ได้ช้าผิดปกติ |
| `read_loops=0` ทุกบรรทัดที่เห็น | ยังไม่มีข้อมูลเข้ามาในช่วงนั้น — สมเหตุสมผล |
| ✅ **`host=127.0.0.1 port=45001`** ช่องว่างเดียวแล้ว | **trim `\r` ทำงานถูก** ยืนยันอีกทาง |

**สิ่งที่ยังไม่รู้ และเป็นสิ่งเดียวที่สำคัญ:** หลังเข้า `AUTHENTICATING` แล้ว
`read_loops` เคยมากกว่า 0 ไหม · เคยมี `bytes_read` ไหม · state เปลี่ยนไปไหนต่อ

**log ตัดตรงนั้นพอดีทุกครั้ง** เพราะ harness `kill` terminal และ MT5 ไม่ flush Experts log

## 🔴 งานเดียวของรอบนี้ — ทำให้ diagnostic ทนการถูก kill

**ห้ามแก้ตรรกะ socket / state machine ใดๆ ทั้งสิ้นในรอบนี้**

เขียน `pump_diag` ลง **ไฟล์ของ EA เอง** แทน Experts log:

| ข้อกำหนด | |
|---|---|
| ที่เก็บ | `FILE_COMMON` → `Common\Files\ea-farm-wire-diag.jsonl` |
| รูปแบบ | JSONL บรรทัดละ 1 pump — `ts` · `state_start` · `state_end` · `read_loops` · `bytes_read` · `pump_us` |
| ★★ **`FileFlush()` ทุกบรรทัด** | นี่คือหัวใจทั้งหมดของงานนี้ · ไม่ flush = ไม่มีประโยชน์ |
| เปิด/ปิด | เปิดครั้งเดียวตอน `Init()` · ปิดตอน `Shutdown()` · **ห้ามเปิด-ปิดทุกบรรทัด** (ช้า) |
| เขียนเมื่อ | `m_verbose == true` เท่านั้น |
| ถ้าเปิดไฟล์ไม่ได้ | log WARN แล้ว**เดินต่อ** ห้ามทำให้ EA ตาย |
| งบเวลา | `pump_elapsed_us` ต้องยังต่ำกว่า 20,000 — ถ้าเกิน ให้รายงานตัวเลขมา **อย่าเงียบ** |

**เพิ่มบรรทัดใน 3 จุดนี้ด้วย** (สำคัญกว่า pump ปกติ):

1. ทุกครั้งที่ `HandleInboundLine` ถูกเรียก → `{"ev":"inbound","type":"<type>"}`
2. ทุกครั้งที่ `EnterState` ถูกเรียก → `{"ev":"state","from":"..","to":"..","reason":"<ผู้เรียก>"}`
3. ทุกครั้งที่ `ScheduleReconnect` ถูกเรียก → `{"ev":"reconnect","backoff_sec":N}`

ข้อ 2 กับ 3 จะตอบคำถาม **32 วินาที** ได้ทันที: EA เข้า `WIRE_FAILED_AUTH` จริงไหม
หรือไปเข้า `WIRE_DISCONNECTED` แล้วไล่ backoff

## ทำไมต้องยอมเสียรอบนี้ไปกับการมองเห็น

เราแก้ตรรกะไป **3 ชั้นแล้ว** และรอบล่าสุดผมยัง**สรุปสาเหตุผิด** เพราะอ่านจาก log ที่ไม่ครบ
· ถ้าเดาต่อโดยยังมองไม่เห็น เราจะเผาเวลาไปเรื่อยๆ แบบเดียวกับที่เสียไปทั้งคืนตอนไล่ MT5 whitelist
ซึ่งจบลงได้เพราะ**เจอวิธีอ่านสถานะจากไฟล์** ไม่ใช่เพราะเดาถูก

> นี่คือ **W3** ในรูปแบบที่เจ็บที่สุด — และตอนนี้มันไม่ใช่ 🟠 อีกแล้ว
> มันคือสิ่งเดียวที่ขวางการแก้ `bad_token`/`duplicate`
