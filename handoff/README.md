# Handoff Bus — ช่องทางคุยระหว่าง Claude ↔ Codex

**สร้าง 2026-07-31** · ที่มา: ตลอดการทำงานที่ผ่านมา ทุกข้อความวิ่งผ่านเจ้าของด้วยการ copy-paste
→ คำถามหาย · ต้องอธิบายซ้ำ · และ **บริบทที่ตกหล่นทำให้ไล่บั๊กผิดทางหลายรอบ**

---

## 1. หลักการเดียวที่ทำให้มันไม่พัง: **กล่องละคนเขียน**

```
handoff/
  to-claude/     ← Codex เขียนเท่านั้น · Claude อ่านอย่างเดียว
  to-codex/      ← Claude เขียนเท่านั้น · Codex อ่านอย่างเดียว
  archive/       ← ย้ายมาเมื่อปิดเรื่องแล้ว (ใครก็ย้ายได้)
```

| กฎ | เหตุผล |
|----|--------|
| **ห้ามแก้ไฟล์ในกล่องของอีกฝ่าย** เด็ดขาด | ไม่มีวัน merge conflict · ไม่มีใครทับข้อความใคร |
| ตอบ = **สร้างไฟล์ใหม่ในกล่องตัวเอง** พร้อม `replies_to:` | ได้ประวัติเป็นเส้น ไม่ใช่ไฟล์ที่ถูกแก้จนไม่รู้ใครพูดอะไร |
| ปิดเรื่องแล้วค่อยย้ายเข้า `archive/` | กล่องที่เห็นคือ "งานที่ยังค้าง" เสมอ |

**ไม่ต้องมี lock · ไม่ต้องมีเครื่องมือ · ทำงานได้ทันทีด้วย git อย่างเดียว**

## 3. รูปแบบข้อความ

ชื่อไฟล์: `NNN-<slug>.md` — `NNN` เรียงต่อเนื่อง **ทั้งบัส** (ไม่แยกกล่อง) เพื่อให้เรียงตามเวลาได้

```markdown
---
id: 001
from: claude          # claude | codex
ticket: SPEC-016      # ticket ที่เกี่ยว หรือ "-" ถ้าไม่มี
type: task            # task | question | answer | handoff | review | fyi
blocking: true        # true = อีกฝ่ายทำงานต่อไม่ได้จนกว่าจะตอบ
replies_to: -         # id ที่กำลังตอบ หรือ "-"
---

# หัวข้อสั้นๆ บรรทัดเดียว

<เนื้อหา>
```

### `type` แต่ละแบบใช้เมื่อไร

| type | ใช้เมื่อ | อีกฝ่ายต้องทำอะไร |
|------|---------|------------------|
| `task` | Claude สั่งงาน Codex | ทำ แล้วตอบด้วย `handoff` |
| `handoff` | Codex ส่งงานเสร็จให้ตรวจ | Claude ตอบด้วย `review` |
| `review` | ผลตรวจ | ถ้า `CHANGES_REQUIRED` → Codex ตอบด้วย `handoff` ใหม่ |
| `question` | ติดจริง ทำต่อไม่ได้ | ตอบด้วย `answer` **ก่อนอย่างอื่น** |
| `answer` | ตอบ `question` | — |
| `fyi` | บอกให้รู้ ไม่ต้องตอบ | — |

## 4. ★★ กฎที่สำคัญที่สุด: `blocking: true` มาก่อนทุกอย่าง

ถ้าในกล่องมีข้อความ `blocking: true` ที่ยังไม่ถูกตอบ
→ **ห้ามเริ่มงานอื่นจนกว่าจะตอบข้อนั้น**

**ทำไม:** ที่ผ่านมาเคยเสียเวลาไปทั้งคืนเพราะคำถามที่ตอบได้ใน 2 นาที
ถูกทิ้งไว้ระหว่างที่ทั้งสองฝ่ายเดินหน้าเดาเอาเอง

`blocking: true` ต้องใช้อย่างประหยัด — ถ้าทุกข้อความ blocking มันจะไม่มีความหมาย
**เกณฑ์: ถ้าเดาผิดแล้วต้องรื้องานทิ้ง = blocking · ถ้าแค่ช้าลง = ไม่ blocking**

## 5. กฎที่ห้ามละเมิด

| # | กฎ | ทำไม |
|---|-----|------|
| 1 | **ห้ามแก้ไฟล์ในกล่องอีกฝ่าย** | ข้อเดียวที่ทำให้บัสนี้ไม่มีวัน conflict |
| 2 | **ห้ามลบข้อความ** — ย้ายเข้า `archive/` เท่านั้น | ประวัติการตัดสินใจคือของมีค่า · หลายครั้งคำตอบอยู่ในข้อความเก่า |
| 3 | **ข้อความต้องมีหลักฐาน ไม่ใช่ความเห็น** | `err=5273 x20 · wire_ready 0` ไม่ใช่ *"socket มีปัญหา"* |
| 4 | บอก **ไฟล์:บรรทัด** เสมอเมื่ออ้างถึงโค้ด | อีกฝ่ายไม่ต้องเดาว่าหมายถึงตรงไหน |
| 5 | **ห้ามใช้บัสนี้แทน spec** | ข้อตกลงถาวรอยู่ใน `docs/specs/` · บัสนี้คือ*การสนทนา* ไม่ใช่*สัญญา* |
| 6 | commit ข้อความพร้อมงานที่เกี่ยว | ข้อความที่ไม่ถูก push = ข้อความที่อีกฝ่ายไม่เห็น |

### กฎข้อ 5 ขยายความ — จุดที่พังง่ายที่สุด

ถ้าคุยกันในบัสแล้วได้ข้อสรุปที่**เปลี่ยนพฤติกรรมของระบบ**
→ **ต้องไปแก้ spec ด้วย** แล้วอ้างถึงใน `answer`

บัสที่กลายเป็นแหล่งความจริงคู่ขนานกับ spec = เรื่องเดียวกันมีสองคำตอบที่ค่อยๆ ต่างกัน
ซึ่งเป็น bug class เดียวกับที่โปรเจกต์นี้ต่อสู้อยู่ตลอด ([02-contracts §8](../docs/02-contracts.md))

## 6. สิ่งที่บัสนี้ **ไม่ได้** แก้ — พูดให้ชัด

| | |
|---|---|
| ❌ ไม่ได้ทำให้ Claude หรือ Codex รันเอง | ทั้งคู่ยังต้องมีเจ้าของเปิด session |
| ❌ ไม่ได้แทนที่ `work-order.md` | นั่นคือ**คิวงาน** · บัสนี้คือ**การสนทนา** |
| ❌ ไม่ได้แทนที่ handoff report | แบบฟอร์มเดิมยังใช้ ([05 §Handoff](../docs/05-collab-protocol.md)) แค่**วางไว้ในบัส**แทนการ paste |

**สิ่งที่มันแก้จริง:** เปิด session ปุ๊บรู้ทันทีว่าค้างอะไร · คำถามไม่หาย ·
ไม่ต้องอธิบายบริบทซ้ำ · และ**ทุกการตัดสินใจมีร่องรอยใน git**

> ถ้าอยากให้ "ต่อเนื่อง" จริงๆ ขั้นถัดไปคือให้เจ้าของตั้ง scheduled run
> ของแต่ละฝั่ง แล้วให้แต่ละ session เริ่มด้วยการอ่านกล่องตัวเอง —
> **บัสนี้เป็นเงื่อนไขที่ต้องมีก่อนถึงจะทำแบบนั้นได้**
